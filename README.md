# 온워크 · 직원 출퇴근 및 생산량 관리 시제품

모바일 웹 시제품입니다. 정적 체험 화면은 Node.js 20 이상에서 실행할 수 있으며, 개발 중인 SQLite 서버 코드와 전체 테스트는 Node.js 24.21.0에서 확인했습니다. 의존성은 `npm ci`로 설치하세요.

## 재연결 후 중간 저장점 상태

- `server.mjs`는 현재 정적 체험 화면만 제공합니다. `public/app.js`는 메모리의 예시 데이터를 사용하며 새로고침하면 입력이 초기화됩니다.
- `lib/`에는 로그인·권한 검사, SQLite 저장, QR 인증, 관리자 수정·야근 승인·삭제·감사 이력, 백업·복구 코드가 있습니다. 아직 실행 서버와 화면에 연결되지 않았으므로 실제 앱에서 사용할 수 있는 완성 기능은 아닙니다.
- 남은 작업: 서버 API 연결, 로그인·비밀번호 변경 화면, QR 표시·카메라 스캔 화면, 관리자 승인·수정·감사 이력 화면, 기기 간 저장·동기화 및 브라우저 통합 검증.
- `scripts/`의 관리자 생성·백업·복구 도구는 개발 중인 DB용입니다. `DATABASE_PATH`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `BACKUP_PATH`, `RESTORE_PATH` 등은 필요한 명령에 환경 변수로 전달하며 실제 값은 저장소에 넣지 않습니다. 이 중간 저장점 작업에서는 도구를 실행하거나 기존 데이터를 변경하지 않았습니다.
- 실제 직원 자료는 `data/`, `private/`, `exports/` 등 Git 제외 경로에 보관하세요. `.gitignore`는 소스 안에 직접 입력한 개인정보나 비밀번호까지 감지하지 못하므로 커밋 내용을 별도로 확인해야 합니다. 테스트와 체험 화면의 데이터는 예시 데이터입니다.

## 실행

저장소 폴더에서 다음 명령어를 한 줄씩 실행하세요.

```bash
node --version
npm ci
npm run dev
```

브라우저에서 http://localhost:3000 에 접속하세요. Codespaces에서는 **포트(Ports)** 탭의 3000 포트에서 **브라우저에서 열기**를 누르세요. 종료는 터미널에서 Ctrl+C입니다.

## 사용 방법

- 직원 화면: 체험 직원 선택, 오늘 출퇴근, 작업별 양품·불량 수량 입력, 내 생산 및 출퇴근 기록 조회.
- 관리자 화면: 조회 날짜 선택, 직원별 출근 현황 및 생산량 합계 조회.
- 기본 근무 08:30~17:30, 점심 12:30~13:30, 휴게 10:30~10:40 및 15:30~15:40.
- 한국 시간 기준으로 기록합니다. 17:30:00을 초과한 퇴근과 다음 날 퇴근은 야근 검토로 표시합니다. 야근 승인이나 수당 계산 기능은 없습니다.
- 어제 날짜를 조회하면 예시 야근 기록을 확인할 수 있습니다.

### 작업 종류 관리

1. **관리자 화면**에서 아래쪽 **작업 종류 관리**로 이동하세요.
2. **새 작업 이름**을 입력하고 **작업 추가**를 누르세요.
3. 기존 작업의 이름을 바꾼 뒤 **이름 수정**을 누르면 수정됩니다.
4. **직원 화면**의 **작업 수량 기록 → 작업**에서 추가·수정된 작업을 선택하고 수량을 기록하세요.

작업 이름은 1~40자이며 빈 이름과 중복 이름은 등록할 수 없습니다. 기존 생산 기록은 기록 당시 작업 이름과 수량을 유지하며, 수정 이후 기록부터 새 이름을 사용합니다. 관리자 합계는 그대로 유지됩니다. 작업 목록 역시 메모리에만 저장되어 새로고침하면 초기화됩니다.

### 직원 관리

1. **관리자 화면 → 직원 관리**에서 이름, 사번, 소속 팀을 입력하고 **직원 추가**를 누르세요.
2. 등록된 직원의 입력 내용을 바꾸고 **정보 수정**을 누르세요.
3. 퇴사자는 **퇴사 처리**를 누르세요. 직원 화면의 **체험 직원** 목록에서 제외되며, 과거 출퇴근 기록과 생산량은 관리자 날짜별 조회와 합계에 계속 포함됩니다.
4. 잘못 비활성화했다면 **다시 활성화**로 복구하세요. 미퇴근 기록도 보존되며 퇴근 입력이 필요하면 다시 활성화해서 처리할 수 있습니다.

이름과 소속 팀은 각각 1~40자, 사번은 영문·숫자·하이픈으로 1~30자입니다. 사번은 대문자로 통일하고 앞뒤 공백을 제거합니다. 비활성 직원을 포함해 사번 중복은 허용하지 않습니다. 이름이 같아도 별개의 직원으로 등록할 수 있습니다.

기록은 변경되지 않는 내부 직원 ID에 연결되므로 이름·사번·소속 팀을 수정해도 서로 섞이지 않습니다. 관리자 표에는 현재 직원 정보와 활성 상태가 표시됩니다. 모든 직원이 비활성이면 직원 화면에서 직원 등록 안내를 표시합니다.

직원 정보도 새로고침하면 초기화되는 시제품이며, 관리자 화면 전환에는 실제 로그인이나 권한 검사가 없습니다.

## 시제품의 한계

로그인, QR 인증, 영구 저장이 없습니다. 직원 선택과 관리자 전환은 체험용이며 권한 검사가 없습니다. 예시 데이터와 입력 내용은 열린 페이지 메모리에만 존재하며 새로고침하면 초기화됩니다. 다른 기기나 탭과 동기화되지 않습니다.

## 검사

```bash
npm test
```

한국 시간 날짜 경계, 야근 기준, 중복 출퇴근, 자정 이후 퇴근, 수량 검증, 날짜별·직원별 합계를 검사합니다.

## 실행 오류 해결

- `listen EPERM` 또는 `EACCES`: 실행 환경에서 포트 열기를 금지한 경우입니다. 포트 사용이 허용된 일반 터미널 또는 승인된 실행 환경에서 실행하세요. 앱 코드로 환경 권한 제한을 해제할 수는 없습니다.
- `EADDRINUSE`: 3000 포트를 이미 사용 중입니다. 기존 서버를 종료하거나 아래 명령어로 3001 포트를 사용하세요.

```bash
PORT=3001 npm run dev
```

기본 수신 주소는 `0.0.0.0`이며 필요하면 `HOST` 환경 변수로 변경할 수 있습니다.

### 시제품 데이터 완전 삭제

**관리자 화면 → 직원 관리 → 완전 삭제 (시제품)**를 누르면 직원 이름·사번·고유 ID와 전체 날짜의 출퇴근·생산량·야근 검토 기록 건수를 확인창에 표시합니다. 야근 검토는 출퇴근 기록에서 계산되므로 출퇴근 건수에 포함됩니다.

- **취소**: 모든 데이터가 그대로 유지됩니다.
- **확인**: 해당 고유 ID의 직원 정보와 모든 출퇴근·생산량 기록을 삭제합니다. 야근 검토 표시도 함께 없어지고 관리자 집계가 즉시 갱신됩니다. 다른 직원과 작업 종류는 유지됩니다.
- **퇴사 처리**: 기록 삭제 없이 신규 입력 목록에서만 숨기고 과거 관리자 조회·집계에 유지합니다.

완전 삭제는 현재 열린 페이지의 메모리 데이터에만 적용하는 시제품 기능입니다. 실제 서버·데이터베이스의 운영용 영구 삭제가 아닙니다. 새로고침하면 예시 데이터로 초기화됩니다. 삭제 후 같은 사번을 등록해도 새로운 내부 ID를 부여합니다.
