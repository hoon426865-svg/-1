# Codespaces에서 기존 온워크에 반영하기

2026-11-09 (한국 시간), 사용자가 공유한 기존 Codespaces 실행 화면에서 `771622eb714d4a32683a05e2afd1cd4035eb23f3`의 **`ONWORK_DEPLOY_OK`와 공개 접속 검사 완료**를 확인했다. 고정 주소는 https://onwork-preview-20261007-01.hoon426865.workers.dev 이다. 품목 JSON 가져오기와 실제 사용자 로그인·업무 확인은 후속 단계다. 상세 확인 범위는 [운영 확장 배포 기록](OPERATIONS.md)을 따른다. 아래 절차는 향후 재실행에도 사용할 수 있다.

## 실행

ChatGPT에서 전달한 검증 완료 커밋 ID의 실행 명령을 **기존 온워크 Codespaces의 터미널**에 붙여넣는다. 커밋을 fetch한 뒤 해당 커밋의 `scripts/codespaces-deploy.sh`에 전체 40자리 커밋 ID를 인수로 전달한다. 현재 작업 브랜치를 바꾸거나 `pull`, `reset`, `stash`할 필요가 없다.

Cloudflare 연결이 없으면 공식 기기 인증 주소와 일회용 코드가 나온다. 해당 주소를 열어 기존 온워크 계정으로 승인하고 터미널로 돌아온다. 이 ChatGPT 환경에서 했던 인증을 Codespaces 인증 완료로 간주하지 않는다. 비밀 토큰을 채팅에 전달하지 않는다.

Node.js 24 이상과 Python 3가 필요하다. Node가 오래됐으면 기존 Codespaces의 NVM으로 24를 준비한다. 의존성 설치, 전체 회귀 검사와 빌드에는 몇 분 걸릴 수 있다.

## 도구가 하는 일

1. 기존 폴더의 `private/operations-deploy-XXXXXXXX/source`에 검증한 커밋만 꺼내고 설치·검사한다. 미커밋 수정과 기존 실행 파일은 건드리지 않는다. 동시에 두 번 실행하면 두 번째 실행을 중단한다.
2. 기존 Worker 버전, DB 연결, 사이트 ID, 패스키 공개키, 호환 설정을 확인한다. 다른 원격 설정을 덮어쓰지 않는다. 무료 Workers/D1 구독 상태를 읽기 전용으로 확인하며 요금제를 바꾸는 API는 호출하지 않는다. 기존 `private/cloudflare-billing-token.txt`가 있으면 원래 위치에서 읽는다.
3. 기존 D1 전체를 `before.sql`로 백업하고 별도 SQLite 사본에 복원한다. 무결성, 외래키, 스키마, 유급 휴게 정책을 검사한다. 원격 DB에 백업을 덮어쓰지 않는다.
4. 0006/0007/0008 중 확인된 현재 스키마에 따라 누락된 0007·0008만 준비한다. 모든 기존 테이블 내용이 사본 변경 전후 동일한지 확인한다. 마이그레이션 이력 테이블이 있으면 새로 적용하는 항목만 같은 SQL 파일 안에서 기록한다. 불완전하거나 알 수 없는 스키마에서는 중단한다.
5. 준비한 작은 SQL 파일을 D1의 원자적 파일 가져오기로 적용한다. 전체 DB 초기화, 실자료 삭제, 재고 생성, 계정·패스키 재등록은 하지 않는다. D1 export/import 동안 짧게 DB 요청이 대기할 수 있다. 공식 동작은 [D1 가져오기/내보내기](https://developers.cloudflare.com/d1/best-practices/import-export-data/)를 참고한다.
6. 다시 export해 새 스키마와 무결성을 검사한다. 백업 사이에 실제 사용자가 자료를 입력했으면 달라진 테이블을 기록한다. 사본에서 증명한 보존 결과와 실제 두 시점의 동일성은 구분한다.
7. 검사 중 다른 Worker 배포가 없었는지 확인하고 기존 `--env preview`에 코드와 정적 파일을 반영한다. 배포 후 상태 응답, 패스키 설정, 비로그인 데이터 접근 거부, 배포 파일 4개의 해시를 검사한다. `production` 환경은 사용하지 않는다.

## 완료 후 품목 기준 적용

터미널에 `ONWORK_DEPLOY_OK`가 나오면 기존 주소에 관리자 패스키로 로그인한다. **설정 → 준비된 품목 목록 가져오기**에서 전달받은 비공개 `onwork-reference-catalog.json`을 선택한다. 파일은 컴퓨터에 다운로드해 두면 되며 Codespaces나 공개 Git에 올릴 필요가 없다.

이 파일에는 참고자료에서 정리한 품목·검사기준 64개가 있다. 기존 도면번호는 건너뛰므로 기존에 수정한 기준을 덮어쓰지 않는다. 원본 자료의 확인 사항과 검사기준이 없는 품목은 관리자가 검토한다. 기준을 가져온 뒤 실제 담당자에게 생산 검토·자재·품질 권한을 지정한다. 초기 재고는 실제 수량을 확인해 입고·조정으로 입력한다.

실제 관리자·직원 패스키 로그인, 휴대전화 사용, 담당자별 업무 동작, 무료 환경의 CPU 한도 확인은 이 도구의 공개 접속 검사와 별개다. 도구가 성공해도 이 항목까지 확인한 것으로 보고하지 않는다.

## 중단·재실행·복귀

- `ONWORK_DEPLOY_STOPPED`가 나오면 그 상태 줄만 전달한다. 전체 DB 백업·로그·인증 파일을 채팅이나 Git에 붙이지 않는다. 도구는 실패한 단계 이후를 진행하지 않으며 원격 DB를 자동 복원하지 않는다.
- 무료 구독 조회 권한이 없으면 운영 변경 전에 멈춘다. 기존 계정에 한정된 Billing Read 토큰을 `scripts/save-cloudflare-billing-token.py`로 숨김 입력해 저장한 뒤 다시 실행할 수 있다. Billing Write는 필요하지 않다. [기존 인증 안내](cloudflare-free.md)를 따른다.
- 인증 오류가 계속되면 해당 실행 폴더의 `source`에서 `./node_modules/.bin/wrangler login --device --browser=false --scopes account:read user:read workers:write workers_scripts:write d1:write`로 연결한 뒤 처음 명령을 재실행한다.
- 재실행은 새 백업 폴더를 만든다. 적용이 완료된 DB 변경은 건너뛴다. DB 변경만 성공하고 코드 배포가 실패한 경우에도 같은 절차를 재실행한다.
- `release.json`에 변경 전·후 Worker 버전과 단계별 결과가 남는다. 이전 코드로 복귀할 때는 기록된 버전을 검토하고 Wrangler rollback을 사용한다. 운영 기록이 추가되었을 수 있으므로 과거 DB 백업을 자동으로 덮어쓰거나 새 테이블을 삭제하지 않는다.
- 백업과 검사 자료는 해당 Codespaces에 비공개로 남는다. Codespaces를 삭제하기 전에 회사의 비공개 백업 위치로 보관한다.

## 준비 단계 검증

합성 DB로 누락된 변경만 적용, 재실행, 기존 행 보존, 부분 스키마 거부, 잘못된 외래키 거부, 이력 불일치 거부, 동시 입력 시 보존·차이 기록을 검사했다. 배포 검사는 다른 DB·인증키·추가 연결 덮어쓰기 거부, 최신 활성 버전 선택, 분할 배포 거부, 인증 설정·접근 제한·정적 파일 해시 불일치 감지를 포함한다. 실제 Cloudflare 배포 결과는 실행 후 `release.json`으로 확인한다.
