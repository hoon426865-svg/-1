# 관리자 선택 초기화

**설정 → 테스트 데이터 초기화**에서 자료 종류(출퇴근, 생산량, 신청·승인, 월별 확정 자료), 직원, 날짜를 선택해 조회합니다. 날짜를 비우면 해당 종류의 전체 기간을 조회합니다. 목록에서 개별 항목 또는 현재 목록 전체를 선택합니다. 한 번에 최대 50건이며 다음 페이지로 이동하면 선택을 새로 합니다.

**선택한 기록 삭제 대상 확인**을 누르면 서버가 연결된 기록을 포함해 삭제 건수를 계산합니다. 출퇴근 원본·집계 예외·출퇴근별 야근 승인, 신청의 처리 이력, 해당 직원·월의 확정본 모든 버전이 포함될 수 있습니다. 생산량 삭제는 해당 생산 기록만 대상으로 합니다. 확정본 삭제만 선택하면 해당 직원·월의 확정본 버전들만 삭제합니다. 원본 출퇴근·신청은 남습니다. 신청 기간이 여러 달에 걸치면 그 기간의 해당 직원 확정본들이 대상입니다.

삭제 사유와 **테스트 기록 삭제** 문구를 입력해야 실행됩니다. 확인은 해당 관리자에게만 유효하고 10분 후 만료됩니다. 목록 조회 후 기록이 바뀌면 서버가 삭제를 거절하고 재확인을 요구합니다. 조회·선택·미리보기·취소는 업무 기록을 삭제하지 않습니다.

## 보존 및 복구 사본

- 직원 명부, 관리자·직원 계정, 패스키, 작업 종류, 근무 기준, QR 사용 이력, 기존 감사 기록은 유지합니다.
- 삭제 직전에 해당 자료와 연결 기록을 담은 JSON 복구 사본을 서버 DB에 보관합니다. 사본 보관과 삭제는 한 트랜잭션으로 처리하므로 중간 실패 시 모두 취소됩니다.
- 사본에는 삭제 대상 업무 기록이 들어 있으며 계정 비밀번호·패스키 정보는 포함하지 않습니다. 사본과 삭제 감사 이력은 유지되며 최근 20건은 관리자 화면에서 조회·다운로드합니다. 이는 DB 전체 백업이나 자동 복원 버튼이 아닙니다. 복원은 별도 자료 대조와 관리자 작업이 필요합니다.
- 서버에 복구 사본과 감사 기록이 남으므로 개인정보의 완전 폐기 기능이 아닙니다. 실제 업무 자료에 사용하지 말고 시험 자료인지 확인합니다.
- 복구 파일을 공개 저장소나 대화에 올리지 않습니다.

## 서버 보호

모든 API는 관리자 인증, 쓰기 요청의 Origin·CSRF 검사를 거칩니다. 서버에서 허용한 자료 종류와 1~50개 ID만 처리합니다. 직원 또는 비로그인은 목록·미리보기·삭제·사본에 접근할 수 없습니다. 선택 변경, 만료, 다른 관리자에게 전달된 확인값, 재전송, 변경된 자료는 거절합니다. 관련 자료가 500건 또는 사본이 250KB를 넘으면 범위를 줄이도록 안내합니다.

`0007_test_data_reset.sql`은 사본·미리보기·행별 삭제 허가 테이블과 조건부 보호 트리거를 추가합니다. 적용 자체로 업무 기록을 삭제하지 않습니다. 보존 대상의 UPDATE 금지와 감사 기록의 삭제 금지는 유지합니다. 원본·신청·확정본 DELETE는 사본에 기록된 정확한 행을 선택한 초기화 트랜잭션 내부에서만 허용됩니다. 트랜잭션이 끝나면 임시 허가와 행 목록은 비워집니다. 정상 API나 SQL의 일반 삭제로 보존 자료를 지울 수 없습니다.

## 배포 및 검증

현재 DB를 별도 백업하고 사본에서 0007을 적용해 기존 계정·패스키·기록·확정본 보존을 확인한 뒤 적용합니다. 테스트는 가상 DB에서 수행합니다. 실제 DB의 초기화 버튼은 배포 검증 과정에서 실행하지 않습니다. Node는 시작 시 같은 마이그레이션을 적용합니다. 이전 코드로 되돌릴 때도 추가 테이블·사본을 삭제하지 않습니다.

검사 대상은 관리자 권한, 계정/패스키 보존, 관련 기록 삭제, 선택하지 않은 기록 보존, 확인 문구·만료·변경 충돌, 미리보기 재사용 거절, 실패 시 전체 취소, 사본 다운로드, 목록 페이지, 모바일 화면입니다.

가상 데이터로 Node 76건, Workers 33건, 브라우저 11건을 확인했습니다. 추가 마이그레이션 전후의 기존 테이블 내용을 대조하고 일반 삭제 차단도 검사했습니다. 실제 Cloudflare 배포 및 실제 계정 로그인은 별도 확인이 필요합니다.
