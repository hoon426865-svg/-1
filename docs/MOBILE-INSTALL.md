# 온워크 휴대폰 설치

기존 온워크 주소를 홈 화면에 설치해 앱처럼 사용한다. Play 스토어·App Store 등록이나 별도 서버 이전은 필요하지 않다. GitHub는 소스와 업데이트 관리, Cloudflare는 사이트와 DB 운영에 계속 사용한다.

주소: https://onwork-preview-20261007-01.hoon426865.workers.dev

## 설치 방법

먼저 전달받은 고정 커밋 명령을 기존 Codespaces에서 실행하고 `ONWORK_DEPLOY_OK`를 확인한다. 휴대폰에서 위 주소를 새로 열면 화면 하단에 **휴대폰에 온워크 설치** 안내가 있다.

- **갤럭시·안드로이드:** Chrome에서 온워크 접속 → 메뉴(⋮) → 설치 및 바로가기 만들기 → 설치. Chrome 버전에 따라 홈 화면에 추가 또는 앱 설치로 표시될 수 있다.
- **아이폰:** Safari에서 온워크 접속 → 공유(일부 레이아웃에서는 페이지 메뉴 → 공유) → 홈 화면에 추가 → 추가. 웹 앱으로 열기가 보이면 켠다.

설치 메뉴가 보이지 않으면 메신저 안의 브라우저 대신 Chrome 또는 Safari에서 직접 주소를 연다. 기존 바로가기의 이름·아이콘이 계속 옛것이면 홈 화면의 바로가기를 지우고 다시 추가한다. 휴대폰에서 앱 데이터나 패스키를 삭제할 필요는 없다.

홈 화면의 온워크 아이콘을 눌러 실행한 뒤 본인 계정으로 로그인한다. 인터넷 연결이 필요하며, 접속이 끊겼을 때 출퇴근·수량·검사 결과를 보관했다가 나중에 자동 제출하는 기능은 없다. 저장 성공 표시를 확인한다.

## 로그인은 설치와 별개

앱 설치는 계정 생성이나 권한 승인이 아니다. PC의 패스키도 설치만으로 휴대폰에 복사되지 않는다. 휴대폰에서 사용할 수 있는 본인 계정의 패스키가 있어야 한다. 기존 PC 로그인은 유지한다.

[관리자별 계정 발급](ADMIN-ACCOUNTS.md)은 다른 관리자를 위한 별도 계정을 만드는 절차다. 이미 등록을 완료한 관리자 계정에 휴대폰 패스키를 추가하는 기능과 다르다. 로그인 문제를 해결하려고 같은 사람의 관리자 계정을 중복 생성하거나 기존 패스키를 삭제하지 않는다. 현재 배포에는 로그인한 계정의 추가 기기 패스키 등록 화면이 없다.

## 구현 및 확인 범위

- 같은 출처의 `/manifest.webmanifest`: 고정 id·start_url·scope는 `/`, 표시 모드는 `standalone`, 온워크 이름과 테마 색상을 사용한다. 로그인별 식별자나 등록권은 넣지 않는다.
- 기존 초록색 체크 로고를 PNG 192/512, maskable 512, Apple touch 180으로 제공한다. 로그인 전에도 설치용 정적 파일은 읽을 수 있다.
- 서비스 워커·오프라인 저장·알림 기능은 추가하지 않는다. 기존 `no-store`, 업무 API 인증, Origin·CSRF 검사, 패스키 RP ID와 사이트 주소를 유지한다.
- Node와 Worker의 정적 파일 경로·MIME·비로그인 접근 차단 회귀 검사, 기존 UI 회귀 검사, 배포 후 설치 파일과 아이콘의 해시·MIME 검사를 사용한다.
- 실제 Android/iPhone 홈 화면 설치·실행·패스키 로그인·카메라 동작은 기기에서 별도로 확인해야 한다. 브라우저 자동 검사 성공만으로 실기기 검증 완료로 간주하지 않는다.
- 이번 변경에는 DB 마이그레이션이 없다. 배포 절차는 [Codespaces 안내](CODESPACES-OPERATIONS.md)를 따른다.
