# 온워크에서 다른 관리자 계정 등록하기

관리자별로 별도 로그인 계정과 패스키를 사용한다. 기존 관리자 비밀번호를 몰라도 현재 관리자 패스키로 본인 확인하면 새 관리자 등록권을 발급할 수 있다. 다른 관리자는 GitHub나 Cloudflare에 가입하지 않고 온워크에서 등록하고 로그인한다.

## 사용 순서

1. 기존 관리자 PC에서 온워크에 패스키로 로그인한다.
2. 설정 → 관리자 계정에서 새 로그인 계정(예: `MGR-01`)과 발급 사유를 입력한다. 이 계정에 온워크 전체 관리자 권한을 부여한다는 확인란을 체크한다.
3. 관리자 추가 · 등록권 발급을 누르고 **현재 관리자 본인의 패스키**로 다시 인증한다.
4. 표시된 로그인 계정과 등록권을 해당 관리자 본인에게 전달한다. 등록권은 15분 동안 한 번만 사용할 수 있으며 창을 닫으면 다시 표시되지 않는다.
5. 다른 관리자는 자신의 PC에서 기존 온워크 주소를 열고, 로그인 화면의 **패스키 등록 · 등록권 입력**을 펼친다. 등록권을 붙여 넣고 **이 기기에 패스키 등록**을 눌러 본인 기기의 PIN·생체인증으로 등록한다.
6. 등록 완료 후 발급받은 로그인 계정(예: `MGR-01`)으로 패스키 로그인한다. 기존 공용 `ADMIN`을 입력하지 않는다. 승인·수정 이력에는 실제 로그인 계정이 남는다.

등록 전 등록권이 만료되거나 전달 중 잃어버렸으면 기존 관리자 PC의 같은 목록에서 **등록권 다시 발급**을 사용한다. 사유와 전체 권한 확인, 기존 관리자 패스키 재인증이 필요하며 이전 미사용 등록권은 무효가 된다.

## 현재 범위

- 새 관리자 계정 생성과 아직 패스키를 등록하지 않은 신규 관리자 등록권 재발급을 지원한다. 기존 직원 계정을 관리자로 승격하지 않는다.
- 등록 완료된 관리자 계정의 패스키 복구·추가 기기 등록·권한 해제는 이번 화면에 포함하지 않는다. 새 패스키 전용 관리자 계정에는 기존 비밀번호가 없으므로 종전 비밀번호 기반 복구 도구를 사용할 수 없다.
- 모든 관리자는 온워크 전체 관리자 권한을 가진다. 관리자별 세부 권한 분리는 제공하지 않는다. 관리자 계정 수는 최대 100개다.
- 원래 ADMIN의 패스키·세션·업무 자료는 새 계정 발급과 다른 관리자 등록으로 바뀌지 않는다.
- 이 기능은 패스키로 운영하는 Worker 앱에 제공한다. 기존 비밀번호 방식 Node 앱은 기존 기능을 유지한다.

## 구현 및 검증

기존 `users`, `passkey_invites`, `passkey_admin_challenges`, 감사 테이블을 사용한다. DB 스키마 변경과 기존 계정 비밀번호 초기화는 필요 없다. 새 계정은 `role=admin`, `employee_id=NULL`, 등록 대기 상태로 만들고 패스키 등록 전 업무 접근을 허용하지 않는다.

관리자 세션·CSRF와 90초 일회용 WebAuthn 재인증으로 작업 종류·대상 계정·사유·전체 권한 확인을 묶는다. 사용자 확인(UV)이 필수다. 등록권은 서버에 해시만 저장하고 만료·사용 여부·계정 상태·발급 관리자 역할을 검증한다. 생성/재발급/감사 저장은 기존 D1 원자적 배치에서 함께 처리한다.

Worker 검사는 별도 계정 등록/로그인/감사 행위자, 기존 관리자 자료 보존, 권한·CSRF·UV·서명·계정·재사용·만료·변경된 작업 거부, 기존 직원 발급의 직원 권한 유지, 감사 실패 롤백과 좁은 등록권 사용 범위를 확인한다. UI 검사는 합성 응답으로 입력 확인·재인증 취소·초안 보존·등록권 표시/제거·503 새로고침 실패 시 유지·401 세션 종료 시 제거·직원 화면 분리·모바일 너비를 확인한다. 실제 WebAuthn 암호 검증은 별도 Worker 테스트가 담당한다.

## 업데이트와 운영 구분

기능 업데이트 코드는 GitHub에 보관하고 기존 Codespaces 배포 도구로 Cloudflare의 동일 온워크 주소에 반영한다. 기능이 설치된 후 일상적인 관리자 발급/등록은 온워크 화면에서 처리한다. 배포 도구는 기존 DB 백업·사본 검사와 정적 파일/비로그인 접근 제한을 확인한다. 이번 기능의 실제 배포와 현장 패스키 등록 완료는 사용자의 실행 결과를 확인한 뒤 기록한다.
