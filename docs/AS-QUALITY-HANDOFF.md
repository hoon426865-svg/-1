# AS 품질 직접 처리 및 도면번호 입력 — 작업 중단 기록

2026-11-09 (한국 시간), 사용자가 오늘 작업을 중단하고 다음 날 이어가기로 했다. 이 체크포인트는 **작업 중인 코드**이며 실제 온워크에 배포하지 않았다. 현재 배포된 버전은 `771622eb714d4a32683a05e2afd1cd4035eb23f3`이다. 운영 DB에 0009를 적용하지 않았다.

## 확정된 요청

- AS 계열은 납품 대상이므로 품질 담당자가 자재 입고 없이 직접 등록하고 검사한다.
- PR·SP·MO·PG는 자재 입고 후 품질이 확인하는 기존 흐름을 유지한다.
- 입고 품목은 긴 목록에서 고르는 대신 도면번호를 입력해 찾는다.

## 현재 구현

- AS 납품 대상/출하검사 이력을 별도 테이블로 추가하는 `0009_quality_deliveries.sql`을 작성했다. 기존 재고와 생산 실적은 변경하지 않는다.
- 품질 권한만으로 AS 대상 등록, 불합격 보류, 재검사, 합격 후 LOT 전체 납품 완료 기록, 사유 있는 등록 취소가 가능하도록 서버 로직을 작성했다. 권한·버전 충돌·재시도 식별자·감사 기록 검사를 포함한다.
- AS 계획 수량은 자재 재고로 더하지 않는다. AS 생산 실적은 남기되 생산 승인 시 재고를 중복 생성하지 않는다. 기존 AS 입고·생산 LOT는 기존 검사 경로에서 보존하며 동일 품목·LOT의 직접 등록을 막는다.
- 품질 화면을 AS 납품 검사 / 입고·생산 LOT 검사로 나누고, AS 등록·검사·완료·취소 화면을 작성했다. 부품 입고와 AS 등록에는 도면번호 입력, 하이픈·밑줄·공백 및 대소문자 대응, 품목 정보 표시, 공급업체 자동 입력을 추가했다.
- 미등록·사용 중지·모호한 도면번호는 차단한다. 부품을 AS 직접 등록으로, AS를 자재 입고로 넣는 것도 서버와 화면에서 막는다.
- Node 설치, Worker 자산 허용 목록, 백업 및 D1 이전 도구, Codespaces 배포 사본 검사와 배포 후 자산 확인을 0009/새 브라우저 모듈에 맞게 수정했다.

## 확인된 검사

- Node 기존 품목·LOT 시나리오, AS 직접 처리 전체 시나리오 및 도면번호 식별 검사 3건 통과.
- 0009를 포함하도록 수정한 SQLite 백업·마이그레이션 사전 검사 8건 통과.
- 수정된 배포 흐름 및 공개 접속 검사 7건 통과(합성 CLI/네트워크, 운영에 연결하지 않음).
- 공유 시나리오 및 Worker 전용 원자성·기존 자료 보존 검사는 작성했으나 **아직 Worker 실행을 하지 않았다**.

## 재개 시 남은 작업

1. 작업 중 변경을 검토한다. Worker 전체 회귀 검사, 실제 브라우저 UI 검사와 시각 확인을 수행한다. 도면번호를 입력한 뒤 상위 새로고침을 눌러도 품목·공급업체·초안이 보존되는지 확인한다.
2. UI에서 품질 전용 직원의 AS 등록→실패/재검사→합격→납품 완료와 자재 담당자의 도번 입고→품질 수입검사를 확인한다. 모호/미등록/다른 계열 입력 거부, 모바일 표시, 탭 변경 시 초안 확인도 검사한다.
3. 0008 운영 DB에 0009만 추가하는 사본 보존 검사를 보강한다. Node 기존 설치 재시작 시 0009가 한 번 적용되고 자료가 유지되는지, 백업/이전 범위에 새 테이블이 포함되는지 확인한다.
4. Worker 마이그레이션 보존 검사의 제목에 있는 ‘재시작 후’ 표현은 현재 테스트 내용에 맞게 고치거나 실제 재시작 검사를 추가한다.
5. `docs/OPERATIONS.md`, `docs/CODESPACES-OPERATIONS.md`의 최신 기능·0009·배포 후 검사 항목 수를 갱신한다. 이전 배포 완료 기록과 새 변경 미배포 상태를 구분한다.
6. 필요한 검사 통과 후에만 기존 작업 브랜치에 반영하고, 검증된 커밋으로 Codespaces 실행 명령을 전달한다. 사용자 작업 폴더와 기존 계정·패스키·DB를 보존하는 기존 배포 도구를 사용한다.

회사 품목·검사기준 JSON은 공개 Git에 넣지 않는다. 공개 소스와 테스트에는 합성 품목만 사용한다. 이 체크포인트를 배포 완료 또는 현장 검증 완료로 보고하지 않는다.
